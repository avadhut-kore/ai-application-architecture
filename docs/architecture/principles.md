# Architecture Principles

This document establishes the non-negotiable architectural principles governing all systems, platform capabilities, and reference implementations within this repository.

Every design decision, pull request, and Architecture Decision Record (ADR) must align with these principles.

---

## 1. Model Output Is Untrusted

All output generated by Large Language Models (LLMs) and Small Language Models (SLMs) is stochastic, unpredictable, and treated as untrusted external input.

* **Validation**: Structured outputs must be parsed and strictly validated against explicit domain schemas (e.g., Pydantic models, Zod schemas, or strongly typed language contracts) before consumption by downstream systems.
* **Bounding**: Numeric ranges, string lengths, and enum values must be verified against domain invariants.
* **Failure Handling**: Applications must define safe, deterministic fallback paths when model output is malformed, incomplete, or fails schema validation.
* **Injection Defense**: Raw model responses must not be rendered directly into web DOMs, passed to database query interpreters without parameterization, or passed to shell command runners.

---

## 2. Deterministic Business Rules Remain Deterministic

Do not migrate deterministic business rules, calculations, or state transitions into a probabilistic model simply because it is technically possible.

* **Role of AI**: Use AI capabilities where natural language understanding, semantic synthesis, pattern extraction, or ambiguous classification provides clear business value.
* **Deterministic Isolation**: Core financial calculations, tax computation, access authorization, inventory increments, and regulatory compliance rules must remain in deterministic, auditable code.
* **Separation**: Models may propose actions or extract parameters; deterministic domain code must validate rules and execute state changes.

---

## 3. Provider Decoupling

Domain entities, business workflows, and application services must not directly depend on vendor-specific software development kits (`openai`, `anthropic`, `google-generativeai`).

* **Ports and Adapters**: Model interactions must occur across clean architectural ports (e.g., `ILlmClient` or `IEmbeddingClient`).
* **Adapter Isolation**: Vendor SDKs are restricted to infrastructure adapter packages.
* **Portability**: Switching between local open-weights models and commercial providers must require configuration adjustments rather than domain code refactoring.

---

## 4. Model Gateway Is Conditional

A centralized model gateway is **not** mandated for every application.

* **When Justified**: A model gateway (or shared gateway middleware) should be introduced only when explicit non-functional requirements justify it, such as:
  * Multi-provider dynamic routing and fallback
  * Centralized token quotas and rate limiting
  * Shared organizational policy enforcement and audit logging
  * Global semantic caching
  * Unified provider cost accounting
* **Direct Interaction**: Small reference applications, focused pattern examples, or isolated local services may communicate directly with local provider adapters through appropriate port interfaces without deploying an intermediary gateway service.

---

## 5. RAG, Memory, Tools, Agents and Workflows Are Distinct

These concepts address fundamentally different concerns and must not be used interchangeably:

* **Retrieval-Augmented Generation (RAG)**: An information retrieval pattern that augments prompts with static or external factual knowledge chunks. It is a data pipeline, not an autonomous agent.
* **Memory**: A state management capability preserving temporal, episodic, or session context across interaction turns. Memory is not a raw database dump and is distinct from document retrieval.
* **Tools**: Discrete, callable capabilities exposed to models with strict parameter schemas and deterministic execution boundaries.
* **Agents**: Goal-directed control loops where a model dynamically evaluates intermediate observations and determines subsequent actions or tool calls.
* **Workflows**: Deterministic, predefined sequences of tasks (directed acyclic graphs or state machines) where transitions are governed by code, not model discretion.

---

## 6. Agent Autonomy Must Be Bounded

Autonomous agents must operate within explicit, enforced execution boundaries.

* **Iteration Caps**: Every agent reasoning loop must enforce a hard upper bound on execution iterations (e.g., maximum 8 tool calls per turn).
* **Timeouts & Budgets**: Agent executions must be bounded by wall-clock timeouts and cumulative token budgets.
* **Cycle Detection**: Systems must detect repetitive or stalled reasoning trajectories and terminate or escalate safely.
* **Unbounded Prohibition**: Unbounded `while True` agent loops with open-ended tool access are strictly prohibited.

---

## 7. State-Mutating Tools Require Authorization

Any tool capable of modifying persistent state, initiating financial transactions, or triggering external side effects must enforce explicit authorization and governance.

* **Least Privilege**: Agents must be granted the minimal set of tools required for their declared purpose.
* **Policy Checks**: State-mutating tools must perform domain authorization checks independent of the model's decision to call the tool.
* **Audit Logging**: All tool invocations, parameters, and return statuses must be recorded in auditable telemetry.
* **Human-in-the-Loop (HITL)**: High-consequence mutations must require explicit human confirmation before execution.

---

## 8. Evaluation Is Mandatory for Probabilistic Behavior

Any application behavior whose output depends materially on probabilistic model inference must be accompanied by measurable, reproducible evaluation criteria.

* **Evaluation Datasets**: Implementations must include versioned evaluation datasets representing realistic enterprise inputs and edge cases.
* **Measurable Metrics**: Outputs must be scored on applicable dimensions (groundedness, context relevance, answer faithfulness, schema compliance, or task completion).
* **Continuous Verification**: Evaluations must be automated and capable of execution during verification pipelines to detect regressions.

---

## 9. AI Systems Must Be Observable

AI interactions must provide operational transparency without compromising sensitive data.

* **Correlation**: Every request must carry correlation identifiers (`trace_id`, `span_id`) across application layers, model calls, and tool invocations.
* **Metadata**: Telemetry spans must capture model identifier, provider name, request duration, success/failure state, and token usage where exposed by the provider.
* **Sensitive Data Redaction**: Raw user prompts, responses, and personally identifiable information (PII) must not be logged to persistent monitoring sinks by default.

---

## 10. Sensitive Data Protection

Sensitive information must be protected throughout the entire AI lifecycle.

* **Prompt Protection**: Unredacted credentials, customer secrets, and confidential identifiers must not be included in prompts sent to external or shared providers.
* **Data Boundary**: Vector stores and embedding indices must maintain strict tenant isolation and access controls.
* **Evaluation Hygiene**: Evaluation datasets and test fixtures must use synthetic or scrubbed enterprise data.

---

## 11. Model Quality ≠ System Quality

A more capable foundation model does not guarantee an enterprise-grade software system.

* **System Design**: System quality is determined by architectural structure, resilient error handling, input validation, retrieval accuracy, tool sandboxing, and deterministic guardrails.
* **Resilience**: Robust systems operate dependably even when underlying foundation models produce variable, incomplete, or degraded responses.

---

## 12. Cost and Latency Are Architecture Concerns

Financial cost and computational latency are architectural constraints that must be evaluated during design rather than retrofitted in production.

* **Efficiency**: Context windows must be budgeted; prompts must avoid unnecessary conversational history.
* **Caching**: Repeated or static queries should leverage deterministic or semantic caching where appropriate.
* **Streaming**: Interactive user interfaces must implement streaming response patterns to optimize Time-to-First-Token (TTFT).

---

## 13. Human-in-the-Loop Is First-Class

Human review and approval must be treated as a native architectural pattern rather than an ad-hoc exception.

* **Durable Suspension**: Systems executing high-risk workflows must support durable state suspension and asynchronous resumption while awaiting human decisions.
* **Escalation Paths**: When confidence thresholds fail or out-of-domain inputs are encountered, the architecture must provide clear paths for human handoff.

---

## 14. Architecture Must Outlive Tools

The architectural patterns, contracts, and business logic established in this repository must remain durable even as specific models, frameworks, vector databases, or agent libraries evolve or become obsolete.

* **Independence**: Do not organize repositories, layers, or abstractions around ephemeral third-party framework idioms.
* **Enduring Value**: Focus on enduring architectural truths: separation of concerns, explicit contracts, bounded contexts, and measurable verification.
