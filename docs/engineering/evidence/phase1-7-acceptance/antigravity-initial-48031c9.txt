Finding F-01 (Severity P2 — Non-Blocking Auxiliary Tooling Defect)
File & Line: examples/agent-execution/verify.py:38
Violated Contract: Component verification helper script must run standalone without import failures.
Reproduction:
powershell
.\.venv\Scripts\python.exe examples/agent-execution/verify.py
Concrete Output:
text
ERROR: test_model_failure_marks_step_failed (tests.test_engine.TestAgentEngine.test_model_failure_marks_step_failed)
ModuleNotFoundError: No module named 'tests.test_executor'
FAILED (errors=2)
Root Cause: Line 38 executes [sys.executable, "-m", "unittest", "discover", "-s", str(AGENT_DIR / "tests")] with cwd=REPO_ROOT, omitting -t str(AGENT_DIR). As a result, Python sets the top-level directory to REPO_ROOT instead of examples/agent-execution, causing internal imports of from tests.test_executor import MockModelClient in test_engine.py and test_execution_boundaries.py to fail.
Impact: Does not affect the agent runtime, engine, or core validation harness. When executed through the repository entry points (scripts/validate.py or scripts/quality.py), or when -t examples/agent-execution is passed, all 81 tests pass cleanly.
Recommended Correction:
python
# In examples/agent-execution/verify.py line 38:
cmd = [sys.executable, "-m", "unittest", "discover", "-s", str(AGENT_DIR / "tests"), "-t", str(AGENT_DIR)]
Finding F-02 (Severity P3 — Operational Latency & Resource Contention Risk)
File & Line: examples/agentic-workflow/workflow/engine.py:314
Violated Contract: Workflow execution must complete within the configured timeout deadline (300 seconds default).
Investigation & Evidence:
In a previous evaluation run, a multi-step workflow timed out at 300.2 seconds.
An independent rerun under controlled conditions completed Scenario 1 in 160.5s and Scenario 2 in 241.0s.
Analysis of CPU execution on qwen2.5:7b indicates prompt evaluation speeds of 9–11 tokens/second and generation speeds of 2.7–3.8 tokens/second.
In multi-step loops, cumulative prompt lengths grow to over 1,300 tokens. When Ollama KV cache hits occur across steps, prompt eval drops to
<
1
ms
<1ms. However, when concurrent background tasks (such as Docker container layer decompression or disk scanning) compete for CPU cores, prompt eval drops to 5–6 tokens/second, extending runtimes beyond 300 seconds.
Impact: Workflows executing on resource-constrained CPU hardware risk tripping the 300-second execution deadline if background processes cause cache evictions or core throttling.
Recommended Mitigation: Document CPU-only sizing constraints in docs/setup/local-ai-environment.md. For CPU-only evaluation runs, either increase the timeout ceiling (execution_timeout_seconds=600) or ensure host cores are not throttled by concurrent background tasks.
